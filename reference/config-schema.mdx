The fastfetch configuration file is a JSON document that controls everything from which logo to display to which system info modules appear in your terminal. fastfetch-config reads and writes this file non-destructively using `jq`, so any fields or comments you add manually are preserved as long as fastfetch-config doesn't manage them directly.

## File location

fastfetch-config stores the configuration at:

```
${XDG_CONFIG_HOME:-$HOME/.config}/fastfetch/config.jsonc
```

On most systems this resolves to `~/.config/fastfetch/config.jsonc`. You can print the exact path at any time with:

```bash
ff config-path
```

## JSON schema

The file references the official fastfetch JSON schema for editor autocompletion and validation:

```
https://github.com/fastfetch-cli/fastfetch/raw/master/doc/json_schema.json
```

Editors that support JSON Schema (VS Code, Neovim with LSP, JetBrains IDEs) will use this URL to provide field hints and inline documentation while you edit the file.

<Warning>
  The file is named `config.jsonc` (JSON with Comments) to align with fastfetch's own naming convention, but fastfetch-config writes standard JSON without comments. If you add comments manually, `jq` operations performed by fastfetch-config will strip them on the next write.
</Warning>

## Default config structure

When you run the installer or `ff reset`, fastfetch-config writes the following default configuration generated by `gen_default_config`:

```json
{
  "$schema": "https://github.com/fastfetch-cli/fastfetch/raw/master/doc/json_schema.json",
  "logo": {
    "type": "auto",
    "source": "",
    "padding": { "right": 4 }
  },
  "modules": [
    "title",
    "separator",
    { "type": "os", "keyIcon": "\uf17c" },
    "host", "kernel", "uptime", "packages", "shell", "de", "wm",
    "cpu", "memory", "swap", "gpu",
    { "type": "disk", "folders": "/" },
    "locale", "break", "colors"
  ]
}
```

This covers the most common system info fields and uses auto logo detection out of the box.

## The `logo` object

The `logo` object controls what is displayed to the left of the system info panel.

| Field | Type | Description |
|-------|------|-------------|
| `type` | string | Logo rendering mode. One of `"auto"`, `"builtin"`, `"file"`, `"chafa"`, `"chafaRaw"` |
| `source` | string | Path to a file or name of a built-in logo; empty string for auto-detection |
| `padding.right` | integer | Columns of space between the logo and the info panel (default: `4`) |
| `width` | integer | Logo width in columns; set automatically by `ff logo fit` or `ff chafa fit` |
| `height` | integer | Logo height in rows; set automatically by `ff logo fit` |
| `color` | object | Maps color slot numbers (`"1"`–`"9"`) to hex color strings, e.g. `{"1": "#FF0000"}` |

### Logo type values

| Type | Behaviour |
|------|-----------|
| `"auto"` | fastfetch detects and renders the distro logo automatically |
| `"builtin"` | Uses one of fastfetch's bundled logo names (e.g. `"arch"`) |
| `"file"` | Renders a plain-text ASCII art file from a path |
| `"chafa"` | Renders an image file (PNG, JPEG, etc.) via chafa in block/pixel mode |
| `"chafaRaw"` | Renders an image via chafa using raw terminal graphics (Kitty / iTerm2 required) |

<Note>
  fastfetch-config selects the type automatically based on file extension when you run `ff logo <path>`. Image extensions (`png`, `jpg`, `jpeg`, `gif`, `bmp`, `webp`, `tiff`) trigger `chafa` mode; all other files use `file` mode.
</Note>

## The `modules` array

Each entry in `modules` tells fastfetch which piece of system info to show and in what order.

### Module entry formats

**Simple string** — uses fastfetch's built-in defaults for that module:

```json
"kernel"
```

**Object** — module with one or more custom properties:

```json
{ "type": "disk", "folders": "/" }
```

**Default `os` module entry** — includes a Nerd Font icon via `keyIcon`:

```json
{ "type": "os", "keyIcon": "\uf17c" }
```

**Custom OS name** — replaces the `os` module with a static label (used by `ff osname`):

```json
{ "type": "custom", "key": "OS", "format": "My OS Name" }
```

### Common module properties

| Property | Applies to | Description |
|----------|-----------|-------------|
| `type` | all object entries | The fastfetch module name |
| `key` | any module | The label shown on the left of the info line |
| `format` | any module | The value shown on the right; can be a static string |
| `keyIcon` | any module | Nerd Font glyph prepended to the key label |
| `folders` | `disk` | Comma-separated mount points, e.g. `"/:/home"` |

## How fastfetch-config writes the file

fastfetch-config uses `jq` for all reads and writes. The `jq_apply` helper pipes the current file through a `jq` filter and atomically replaces it via a temp file. This means:

- Fields that fastfetch-config does not manage (e.g. `display`, `general`, custom module options) are **left untouched**.
- The only side effect is that in-file comments are stripped on the first write, because `jq` does not preserve JSONC comment syntax.

Run `ff status` to inspect the current logo, OS name, and module list without modifying anything.
